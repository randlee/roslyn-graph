Turn any .NET assembly
into a queryable knowledge graph.

RoslynToRdf extracts a complete type graph — classes, members, parameters, inheritance, interfaces, exceptions, and attributes — and emits standards-compliant RDF (N-Triples or Turtle) you can load into Oxigraph or any triple store and query with SPARQL.

$ dotnet tool install --global RoslynToRdf

Use cases

What people do with it

Five jobs. One graph. Each is a real workflow grounded in the extracted ontology.

“I'm refactoring a legacy codebase and need a map”

Get the inheritance tree, every interface implementation, and all cross-type dependencies in one artifact. --include-private exposes the hidden coupling that grep misses, so you can plan a safe, incremental refactor instead of discovering landmines mid-edit. 

# Every subclass of a legacy base type
PREFIX dt: <http://dotnet.example/ontology/>

SELECT ?type ?name WHERE {
  ?type dt:inherits* ?base .
  ?base dt:name "LegacyController" .
  ?type dt:name ?name .
}
── powers ── inherits · implements · nestedIn · hasMember · --include-private

“I audit architecture rules as declarative queries”

Exception contracts (<exception>), cross-references (<seealso>), and attributes all become queryable edges. A boundary violation or a deprecated-API touchpoint is one SPARQL statement, not a code review. 

# Every method documented to throw ArgumentNullException
SELECT ?method ?typeName WHERE {
  ?method a dt:Method ;
          dt:throws ?ex ;
          dt:memberOf ?type .
  ?type dt:name ?typeName .
  ?ex dt:name "ArgumentNullException" .
}
── powers ── throws · relatedTo · hasAttribute · hasMember

“I load .NET types into a knowledge graph”

Standards-compliant output with deterministic, collision-safe IRIs. Emit Turtle for humans or N-Triples for streaming loads into Oxigraph, then link your assembly's types to the rest of your graph. 

# Turtle, custom base URI
roslyn2rdf MyAssembly.dll -o types.ttl -f turtle \
    -b "http://mycompany.com/types/"
── powers ── NTriples · Turtle · --base-uri · IriMinter

“I build a complete migration checklist”

Enumerate every type and member carrying a given attribute — deprecated markers, serialization contracts, dangerous reflection surfaces — and get the full, ranked set of touchpoints before you touch anything. 

# Find every type decorated with a given attribute
SELECT ?type ?name WHERE {
  ?type dt:hasAttribute ?attr .
  ?attr dt:attributeType ?attrType .
  ?attrType dt:name "ObsoleteAttribute" .
  ?type dt:name ?name .
}
── powers ── hasAttribute · attributeType · constructorArguments

“Every build publishes an up-to-date graph”

The CLI is a thin wrapper over RoslynToRdf.Core, so you can consume the extractor programmatically or run the dotnet tool in CI and ship a fresh type-graph artifact with every build — no manual steps. 

# Deterministic pipeline artifact
roslyn2rdf src/bin/Release/MyApp.dll \
    -o artifacts/types.nt -q
── powers ── RoslynToRdf.Core · dotnet tool · --quiet · CI-ready
How it works

Three steps, no magic

1 · Extract

  • Roslyn loads the assembly
  • walks types + members
  • parses XML docs

2 · Emit

  • N-Triples or Turtle
  • collision-safe IRIs
  • deterministic output

3 · Query

  • load into Oxigraph
  • SPARQL your graph
  • or browse with the viewer
Install

Get it in one command

Ships as a .NET global tool. Requires .NET 8 SDK to build from source. 

# Install the tool
dotnet tool install --global RoslynToRdf

# Extract a type graph
roslyn2rdf MyAssembly.dll

# With options
roslyn2rdf MyAssembly.dll -o types.ttl -f turtle --include-private
